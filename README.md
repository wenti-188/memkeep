# MemKeep

给 LLM Agent 用的长期记忆层：从对话里抽取事实、判冲突、按保留分遗忘、按问题检索。

不是"把聊天记录塞进向量库再 top-k"，而是把对话变成**结构化、可冲突消解、会过期**的记忆条目，再按问题类型走不同的检索策略。

---

## 它解决的问题

| 裸上下文 | RAG over 聊天记录 | MemKeep |
|---|---|---|
| 越长越贵，超过窗口就丢 | 召回一堆重复、过期片段 | 条目级去重，同属性只留最新或并存 |
| 说过的话前后矛盾，模型自己打架 | 无法判断哪条该信 | 冲突判定 → supersede / coexist，带时间 |
| 没有遗忘，三年前一句玩笑还在 | 旧条目 forever 占召回位 | 保留分 `base × 频率 × e^(-λ·天数)` |
| 未知问题照样编 | 未知问题照样编 | 检索不到就不答（拒答率可测） |

---

## 架构

```
对话 → 抽取器(LLM, 双采样并集) → 冲突判定(保守) → 写入(SQLite + 1024 维向量)
                                                        ↓
问题 → 意图路由(preference / time / fact / semantic) → 混合打分 → top-k 拼上下文 → 作答
```

四层：

- `core/llm.py` — Ollama 封装，标准库 urllib，无第三方依赖
- `core/extractor.py` — 事实抽取（5 类）+ 冲突判定
- `core/writer.py` — 写入流水线：同值去重 → 查冲突 → update/coexist → 入库
- `core/retriever.py` — 混合打分 `0.45·sim + 0.42·关键词 + 0.13·保留分`，类别加权
- `storage/db.py` — 三表 `memories / sessions / conflicts`，保留分公式与状态机

## 评测

50 题跨会话记忆题，7 类：identity / preference / goal / event / tech / relation / unknown。
20 段虚构求职对话（2026-08 ~ 2026-11）作为记忆来源，其中 3 组故意埋冲突。

| 轮次 | 配置 | 准确率 |
|---|---|---|
| v1 | 类别粗筛检索 | 50% |
| v2 | 混合打分，top_k=8 | 64% |
| v3 | 收紧 top_k=5 / min_score=0.28 | 62%（挤掉正确条目） |
| v4 | 去掉拒答选项 + 抽取加规则 | 72%（unknown 崩到 0%，评分词表没覆盖新表达） |
| v5 | 双采样并集 + 事件注入日期 + 拒答词表扩展 | 82%（unknown 回到 100%） |
| v6 | 同批次结果合并 + update 保留旧值 | 82% |
| v7 | 中文 n-gram 关键词 + 三路 RRF | 82%（event 70%，tech 83%） |
| v8 | update 去嵌套 + 结论 | **84%**（event 90%，unknown 100%，goal 50%） |

分项（v8）：identity 9/10、preference 9/10、goal 3/6、event 9/10、tech 5/6、relation 4/5、unknown 3/3。

七轮调下来从 50% 到 84%。剩下 8 题的失败原因：

- **抽取漏采 4 题**：985 院校层次、408 项目起始时间、首字延迟 37s→1.1s、"大模型/算法"方向。7B 模型单次抽取有召回上限，prompt 约束到第三轮就边际递减。
- **评分口径 2 题**：答案语义正确但表述与关键词表不匹配（"二面挂了"只答成"挂了"）。
- **语义判断 2 题**：模型把"能跑大模型"判成"配置不足"——它没把"正在跑的 qwen2.5 7B"当证据。

运行：

```bash
python seed_load.py          # 重放 20 段对话建库（约 20 分钟，双采样）
python eval/run_eval.py      # 跑 50 题（约 12 分钟）
```

## 跑起来

```bash
# 依赖：Ollama + qwen2.5:7b + bge-m3
python app.py                # http://127.0.0.1:5051（端口可用 MEMKEEP_PORT 覆盖）
```

界面左侧对话，右侧是记忆面板：能看每条记忆的类别、保留分、状态，能单条删除。
只有陈述句会写入记忆，问句不抽事实——否则"用户在问什么"会被当成记忆存进去。

## 设计取舍

1. **抽取宁多勿少，冲突宁并勿删。** 漏抽一条就永久丢事实；误并存只是多一条，检索时靠分数排序还能救。
2. **事件类强制注入对话日期。** 7B 模型不会自觉把时间写进 value，靠 prompt 提醒三次都漏，只好在写入层硬加。
3. **拒答放在两处。** 检索层 `min_score` 兜底 + 作答 prompt 允许"没记录"，因为只靠 prompt 时模型会为了"必须作答"而编。
4. **保留分不参与主排序。** 只占 0.13 权重，避免"最近说的"压过"最相关的"。
